## Traps and gotchas
- **Destructive migrate (highest value).** `migrate_into_landmarks_usa.sql` §3 does `DELETE FROM landmarks_usa WHERE source IN (SELECT DISTINCT source FROM lm_places_usa)` then re-inserts from lm_places_usa, which holds NO enrichment (the RDAP chain runs against landmarks_usa). It would have destroyed enrichment on ~1.18M rows (1,139,855 osm, 24,721 wikidata, 14,149 dotgov, 6,075 nces_ipeds). Fix: `migrate_ca_cde.sql` scoped INSERT. Boris: never run the old one.
- **Truncated onpremises run masquerading as a bug.** The first pass stopped ~2.5M candidate rows (chunks 1–7 changed 0), reported 272 changed when a full run changes 984,762. This single cause explained BOTH the ~11,249 count gap AND the Cloudflare addresses appearing in the on-premises set. No bug in ip_chunks. The AI had built a matching-brittleness theory on stale data; falsified by V1.
- **QUOTE_NONE mandatory.** The CDE file is tab-delimited, unquoted, with bare `"` in school names; the default csv dialect collapsed the 8.8MB file to 73 parsed rows SILENTLY.
- **Captcha as HTTP 200.** CDE serves a ~15KB Radware captcha as `200 text/html` after the first fetch; a downloading loader parses it as data and reports success. Loader validates CDSCode header and refuses. The same protection is expected on other state sites.
- **The 45-minute "hang" was self-inflicted.** It was the AI's own GitHub rate-limit wait loop (HTTP 429, `sleep` against the reset epoch inside one tool call) — indistinguishable from a hang to Boris. The database was never touched. The AI had wrongly pre-assumed a DB lock and written lock-timeout hardening around that assumption. Standing fix: never blind-sleep for rate limits; push via git (not subject to the API limit) and hand over the PR link.
- **store_direct whole-table seq scan.** Creates a temp `stage` table, COPYs the batch, joins against 12.8M rows with NO ANALYZE → planner has no row estimate for `stage` and hash-joins (seq scan) on every flush. 6 flushes × ~5 min = the 1,862s rdap time. Fix #69: `ANALYZE stage` + index on `stage(ip)`. (AI inference from timings, not EXPLAIN — testable.)
- **Hostname count overstated the pool ninefold.** 5,165 distinct hostnames collapsed to 556 addresses; "4,839 single-ZIP hostnames" became 379 single-ZIP addresses. School-website vendors (Edlio/Finalsite/Apptegy/SchoolMessenger-type) give each school a hostname but serve from a handful of IPs. The AI flagged this was its own error in the budget-wasting direction, the third such wrong-population number this session (hostname estimate, stale coverage figures, probe three-denominator).
- **overture-zip is required even when the ZIP is already in the file.** `onpremises` reads only `overture_zip`; overture-zip is the step that copies `postcode`→`overture_zip` with `overture_zip_source='postcode'`. Skip it and every CA row falls into rule 1 as NULL.
- **z1/z2 null an ISP's ZIP but not a provider's.** When a provider name is an unmatched variant (e.g. "Microsoft Corp"), rule 2 does not fire and adjacency then uses the provider's registered ZIP — exactly how Redmond 98052 landmarks at 98005/98008/98033/98034 became on-premises. AI said it will fix this regardless of the larger rule change.
- **Probe three-denominator bug.** "rows with ZIP+website", "distinct ZIPs", "distinct hosts" were each counted over a different row set, read as mutual corroboration. Plus it detected StatusType and then ignored it, counting 124 closed/pending schools. Fixed #71.
- **Probe column/pattern specificity.** Anchored `^zip` missed Texas "School Zip"; `\bstatus\b` broke CA "StatusType" and matched TX "Magnet Status"; taking one column per role would read the district's ZIP against the school's website. Fixed #72; caught only by re-running fixtures.
- **Unmerged PRs silently break sequences.** `git pull origin main` prints "Already up to date" and brings nothing when the needed code is only on an unmerged branch; `ca-cde` existed only on `geo-ca-cde-schools`. Broke two command sequences. Workaround used: Path A (checkout the branch).
